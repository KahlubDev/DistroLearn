| `workflow_dispatch` | yes | Not in the plan. Added so a ref can be verified without opening a PR, which is what made the red run possible with no probe PR |

`workflow_dispatch` on a public repo allows any user with write access to trigger the
workflow manually. It runs no untrusted input: `ref` selects a git ref, and the job runs
that ref's workflow file with read-only permissions. Worth knowing, not a finding.

## Observations, not findings

1. **Go cache annotation.** The green run carries a warning: `Restore cache failed:
   Dependencies file is not found`. Expected. `services/go.sum` does not exist while the
   module has no dependencies, and `setup-go` needs a `go.mod` or `go.sum` to key its
   cache. Non-fatal, and the cause is documented in the workflow comment. Already
   scheduled for `docs/plans/018-database.md`.

2. **`ubuntu-latest` will migrate to Ubuntu 26 on 2026-10-19**, per a runner notice in the
   green run. `ubuntu-latest` is what the plan specifies, and the pin table names the
   label, not an image version. Worth a check after the migration date.

3. **Concurrency cancels superseded runs** on the same ref. A rapid push sequence leaves
   only the newest run. Correct behaviour, worth knowing when reading run history.

4. **Check name is `make check`.** Confirmed from both the job name and the check-runs
   API on commit `d92165b`. This is the string to select when adding a required status
   check to a branch protection rule.
